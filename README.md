# Напоминалка для Windows 11 (Python + SQLite3 + tkinter)

Приложение-напоминалка с хранением в базе SQLite3, системными уведомлениями
Windows 11 и popup-окнами поверх всех окон. Уведомления работают даже при
свёрнутом окне программы.

## Структура проекта

| Файл              | Назначение                                              |
|-------------------|---------------------------------------------------------|
| `db.py`           | Слой работы с SQLite3: схема, CRUD, автопросрочка       |
| `notifier.py`     | Уведомления: winotify → MessageBoxW → tkinter popup     |
| `main.py`         | GUI на tkinter + фоновый планировщик проверок           |
| `requirements.txt`| Зависимости                                             |
| `reminders.db`    | Файл базы данных (создаётся автоматически при старте)   |

## Установка и запуск (Windows 11)

```bat
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Зависимость `winotify` опциональна — это современная замена `win10toast`
для тостов Windows 11. Если её нет, приложение само использует:
1. нативный `MessageBoxW` (popup поверх всех окон через ctypes, без зависимостей);
2. резервный tkinter-popup с атрибутом `-topmost`.

`tkinter` и `sqlite3` входят в стандартную поставку Python для Windows.

## Возможности

* **Добавить напоминание** — кнопка «➕ Добавить» (заголовок, описание, дата и время).
* **Удалить** — кнопка «🗑 Удалить» (с подтверждением).
* **Отметить «Готово» / «Отменено»** — соответствующие кнопки (двойной клик по строке = «Готово»).
* **Фильтр по статусу** — выпадающий список: Все / Ожидает / Готово / Просрочено / Отменено.
* **Автопросрочка** — фоновый таймер каждые 15 секунд:
  * наступившие напоминания → уведомление (тост Windows или topmost popup);
  * не выполненные после срабатывания → автоматический перевод в статус **«Просрочено»**.

## Статусы

| Статус      | Смысл                                                    |
|-------------|----------------------------------------------------------|
| Ожидает     | Создано, время ещё не наступило                          |
| Готово      | Выполнено вручную                                        |
| Просрочено  | Время вышло, но напоминание не отмечено выполненным      |
| Отменено    | Аннулировано вручную                                     |

## Схема БД

```sql
CREATE TABLE reminders (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    title       TEXT NOT NULL,             -- заголовок
    description TEXT DEFAULT '',           -- описание
    due_dt      TEXT NOT NULL,             -- 'YYYY-MM-DD HH:MM:SS' — дата/время срабатывания
    status      TEXT DEFAULT 'Ожидает',    -- Ожидает | Готово | Просрочено | Отменено
    created_at  TEXT NOT NULL,
    notified    INTEGER DEFAULT 0          -- 1, если уведомление уже показано (защита от дублей)
);
```

Таблица создаётся автоматически (`CREATE TABLE IF NOT EXISTS`) при каждом старте приложения.

## CLI-менеджер паролей (passman.py)

Отдельное приложение в этом же репозитории: безопасное хранение паролей в SQLite3
с шифрованием Fernet и входом по мастер-паролю (SHA-256).

### Установка и запуск

```bash
pip install cryptography
python passman.py <команда>
```

### Структура кода

| Файл | Назначение |
|---|---|
| `passdb.py` | Работа с SQLite3: создание таблиц при старте, CRUD записей, хранение хеша мастер-пароля |
| `crypto_utils.py` | Шифрование Fernet (ключ в файле `.key`), хеширование SHA-256 с солью |
| `passman.py` | Основной CLI-обработчик (argparse + интерактивный ввод) |

### Как это работает

* **Первый запуск** — программа запрашивает мастер-пароль (ввод дважды) и
  сохраняет его **хеш SHA-256 + соль** в таблице `settings` базы `passwords.db`.
* **Последующие запуски** — вход только после ввода мастер-пароля.
* Пароли записей шифруются **Fernet** (`cryptography`); ключ хранится в файле
  **`.key`** и генерируется автоматически при первом запуске.
* Таблицы проверяются и создаются при каждом старте (`CREATE TABLE IF NOT EXISTS`).

### Команды

```bash
python passman.py add                 # добавить запись (название, логин, пароль)
python passman.py add --name Google --login user@gmail.com   # то же из аргументов
python passman.py get Google          # показать пароль (расшифрует после входа)
python passman.py list                # список всех записей (названия и логины)
python passman.py delete Google       # удалить запись по названию
python passman.py new                 # создать новый надёжный пароль (генератор)
python passman.py new --length 24 --save-to GitHub           # сгенерировать и сохранить
```

Флаги: `--update` (перезаписать существующую запись в `add`), `-y/--yes`
(без подтверждения в `delete`).

### Безопасность

* В базе нет ни мастер-пароля, ни паролей в открытом виде — только хеш SHA-256
  с солью и Fernet-токены.
* Файл `.key` создаётся с правами `0600`; **никогда не добавляйте `.key` и
  `passwords.db` в git** (уже внесены в `.gitignore`).
* Без файла `.key` расшифровать базу невозможно.
